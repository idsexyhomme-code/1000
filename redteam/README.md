# Korean LLM Safety QA / Red-Team (MVP core)

**한국어 LLM 출시 전 안전성 검증 리포트 + 레드티밍 데이터셋을 만드는 인프라.**
(WorkRadar와 병행하는 별도 B2B 제품. 정당한 AI 안전성 검증 = 방어 목적, NIST GenAI Risk Profile / EU AI Act 흐름 대응.)

## 왜 이 구조인가 (어젯밤 'so what' 교훈)
플랫폼(업로드/대시보드/CRUD)은 쉬운 20%. **진짜 해자 = 아래 3개:**
1. **위험 택소노미** (`taxonomy.json`) — 한국어 특화 9개 카테고리 + 심각도 4단계 + outcome 정의.
2. **레드팀 프롬프트 라이브러리** (`prompts_seed.jsonl`) — 모델이 제대로 거부하는지 검증하는 프로브. (critical 유해 프롬프트는 미포함 — 고객사 인증 하 보안팀이 작성.)
3. **평가 방법론** (`redteam_core.py`) — 2인 이상 교차검수 + 안전-우선 조정 + 집계.

## 파일
| 파일 | 역할 |
|---|---|
| `taxonomy.json` | 위험 분류 체계 (탈옥/유해조언/개인정보/환각/편향/저작권/의료/금융/미성년) + 심각도 rubric |
| `prompts_seed.jsonl` | 시드 레드팀 프로브 (안전-테스트 수준) |
| `redteam_core.py` | 평가 엔진 (무의존성): `reconcile`(교차검수 조정, 안전-우선), `evaluate`, `summarize`, `export_dataset` |
| `report.py` | 고객용 안전성 리포트 렌더 + 엔드투엔드 데모 |

## 실행 (데모)
```bash
python3 report.py    # 모의 응답+2인 검수로 파이프라인 실증 → 리포트 + demo_dataset.jsonl
```

## 상품화 (1차)
**한국어 LLM 레드티밍 1,000문항 패키지**
- 입력: 고객 모델(또는 API) + 위험 카테고리 선택
- 프로세스: 프로브 실행 → 응답 수집 → 위험 태깅/심각도 → 2인 교차검수 → 불일치 사람 판정
- 산출물: 실패 프롬프트+응답, 위험분류, 심각도, 개선권고, **JSON 데이터셋** + **안전성 리포트(PDF/대시보드)**
- 타깃: 국내 AI 챗봇 스타트업, 사내 LLM 도입 기업, 교육/상담/커머스 챗봇 개발사

확장: 의료/금융/법률 환각 검증(도메인 전문가 필요, 단가↑, 2차).

## WorkRadar에서 재활용한 패턴
택소노미+태깅+심각도 스코어+정직한 방법론+무의존성 엔진+JSON/리포트 export — 전부 WorkRadar 엔진에서 검증한 구조. 제품은 다르지만 뼈대는 이식.

## 정직성
리포트는 **테스트한 프로브 집합에 한함**(전체 안전 보장 아님). 심각도는 고정 rubric, 검수자 불일치는 사람 판정으로 넘김. 무기화된 유해 프롬프트/출력은 생성하지 않음.
